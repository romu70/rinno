01

Contexte

Passionné par les polices de caractères et le street art, je capture et collecte des photos, qui s'accumulent sur mon téléphone depuis des années.

Je me suis donc lancé dans le développement d'une galerie virtuelle, calquée sur celle de DuckDuckGo que j'aime beaucoup, pour exposer ces images.

Challenge

  • Aiguiser mes compétences en développement web
  • Créer une galerie performante et esthétique
  • Gérer efficacement de nombreuses images
  • Approfondir l'approche composants en web

Bien sûr, la galerie devait être utilisable sur téléphone et sur écran large.

03

Trois itérations

  1. Itération 1

    Construire la galerie

    Astro
    Choix de la stack
    Sur les conseils d'un ami développeur front-end, Guillaume Denier, j'ai choisi Astro : génération statique, proche des standards web, approche composants accessible. Promesses tenues !
    Hébergement
    Code sur GitHub, site statique sans collecte de données : GitHub Pages s'imposait, avec son pipeline CI/CD intégré.
    Collections par thème
    Les 2 galeries reposent sur les Content Collections d'Astro. Pour mieux connaître le système, l'une est en markdown, l'autre en JSON.
    Galerie responsive
    J'ai développé en TypeScript tout le fonctionnement de la galerie : formats portrait / paysage, navigation, clavier, etc.
  2. Itération 2

    Automatiser le traitement

    Gemini

    Constat : la flemme

    Les images s'accumulaient et ma motivation baissait. Modéliser mon propre user journey m'a éclairé : ouvrir l'image, récupérer sa position, la chercher sur OpenStreetMap, renseigner les métadonnées dans un fichier Astro, redimensionner, compresser… C'est très (trop) long.

    Solution : Gemini

    En 2 heures avec Gemini, un script qui me soulage de toute la partie chronophage. Une fois les images sur mon ordinateur, il se charge des traitements ; je ne renseigne plus que ce qu'il ne peut pas faire.

  3. Itération 3

    Bonjour Claude, ça skill ?

    Skill Claude

    Constat : la flemme bis

    Malgré le script, j'accumulais toujours les photos : il accélère le process, mais pas assez pour m'inciter à publier.

    Ce que fait le script

    • Scanne le dossier inbox
    • Redimensionne les images
    • Extrait la géolocalisation et la date de prise de vue
    • Crée les fichiers Astro des nouvelles images

    Ce qui restait à ma charge

    • Transférer les photos de Downloads vers inbox
    • Nommer les photos
    • Renseigner les métadonnées

    Et comme il fallait le faire image par image, c'est là que je perdais du temps.

    Solution : un skill Claude

    J'ai d'abord supprimé le nom des images, qui ne rimait à rien, pour mettre en avant les artistes et le type des fonts. Puis, avec Claude, j'ai rédigé un skill qui prend en charge toute la partie pénible et répétitive :

    • Transférer les images de Downloads vers inbox.
    • Lancer un sous-agent qui caractérise les images, par exemple une font serif ou sans-serif. Quel gain de temps !
    • Pour le street art, identifier la signature de l'artiste.
    • Valider l'ajout des images.

    Au lieu de modifier chaque fichier, Claude me fait une liste de propositions que je valide, amende ou refuse, en une seule passe.
